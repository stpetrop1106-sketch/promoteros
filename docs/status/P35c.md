## Done
- All four form screens now group related fields under `Section` instead of ad-hoc `<h2>`s, use
  one shared banner shape for every error/success message, and use a tappable 44px chip for every
  checkbox/radio instead of a bare browser input.
- `npx tsc --noEmit` clean, `npm test` 200/200, `npm run build` completes.
- Found and fixed a real, pre-existing 500 on `/campaigns/new` and
  `/campaigns/[id]/shifts/new`: both forms took the translator as a prop from their (server)
  page, which crashes on every request — invisible to `npm run build` because both routes are
  `force-dynamic`. Fixed by having each Client Component build its own translator, matching
  `promoter-form.tsx`. This is a boundary bug fix, not a logic or behavior change — same category
  CLAUDE.md's server/client section warns about, just a different flavor (a function prop, not a
  `"use server"` export).
