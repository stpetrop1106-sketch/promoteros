## Incident I3 — five agents killed simultaneously by the session limit

All five in-flight agents died at once on a 429. Nothing was corrupted: P0, P1, P2, P3a and P15 had
already finished and were `in_review`; P4 died mid-parcel; P3b, P5 and P0c had not written a line.

**The i18n type contract paid for itself here.** P4 had written `app/campaigns/_shared.ts` referencing
`campaigns.*` keys but was killed before appending them to the dictionaries. The build fails loudly
instead of shipping a screen with missing labels — which is exactly the failure mode D9 was designed
to prevent.

**Management change: maximum two concurrent agents from now on.** Five parallel Opus/Sonnet agents
exhausted the session budget faster than they produced work, and a killed agent costs its whole
context. Two at a time is slower per wall-clock hour and strictly faster to a finished parcel.

## Open incidents

### I2 — Migration `0004` was never applied

Verified directly against the live database: `waitlist_signups` returns `PGRST205` (table not found)
while every other seeded table returns 200. The migration file exists but nobody ran it.

**Impact:** the waitlist form on the public landing page fails for any real visitor. It is the only
call-to-action on that page.

**Fix:** apply `supabase/migrations/0004_waitlist_signups.sql` in the Supabase SQL editor.

**Process lesson, already applied:** writing a migration and applying it are separate acts, and no
agent can do the second. The registry in this file now tracks *applied*, not *written*.

### I1 — The project is not its own git repository

`git status` from the project directory reports the whole of `C:\Users\Stella` — the repo root is the
home directory, not `AI Saas`. Consequences, all bad:

- `git status` is unusable for verifying an agent's scope, which is one of our collision checks
- the plan's "one branch per parcel" is not possible
- any `git add -A` would stage personal files: browser profiles, `NTUSER.DAT`, `.claude.json`,
  unrelated CSVs and databases

**Nothing has been committed, and no agent has been given git access**, so no damage has occurred.

**Recommended fix:** `git init` inside `AI Saas` so the project versions itself. This is the user's
home-directory setup, so the manager is flagging rather than changing it unilaterally. Until it is
resolved, scope verification is done by reading each agent's `## Files touched` and by timestamp,
not by git.
