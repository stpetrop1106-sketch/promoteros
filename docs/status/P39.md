## Notes for the manager
- **Idempotency:** every automatic message inserts a `pending` row in `message_dispatches` BEFORE calling Resend;
  `unique (promoter_id, kind, period_key)` makes a second run's insert fail, so it skips. Skipped/failed rows (and
  pending rows stale > 30 min) can be re-claimed only via an update conditional on `attempts`, so exactly one run
  wins; the Resend `Idempotency-Key` is derived from the row id, so even a re-sent stale row is de-duplicated
  provider-side. Unit-tested with three concurrent runs → one email.
- **No email configured:** nothing is attempted and nothing is recorded (so the period stays claimable once you
  configure it); invitations keep the clipboard flow; the cron returns `{emailConfigured:false}`; the settings page
  says what is missing and lists every promoter with a ready link. Without 0017 the page degrades as described above.
- **Env (Vercel):** `RESEND_API_KEY`, `EMAIL_FROM` (both required for email), `CRON_SECRET` (without it the cron
  route rejects everything). Vercel sends `Authorization: Bearer $CRON_SECRET` to cron routes automatically.
- **Schedule:** `vercel.json` → `0 4 * * *` (04:00 UTC = 07:00 Athens summer / 06:00 winter; Hobby fires within
  the hour). One job because Hobby allows once a day; early enough for morning check-in links, and well past
  Athens midnight in both seasons so "the 1st/15th" is never read across a date line. Check-in links run first.
- **Capacity:** paced at one request per 550 ms (Resend 2/s), `maxDuration = 300` with a 240 s send budget ≈ 400
  emails per run; recipients beyond that are reported as `notStarted` and, being unclaimed, would only go on a
  re-trigger the same Athens day. Fine for today's rosters; at scale, move to Resend's batch endpoint. If the
  project does not have Fluid compute, `maxDuration = 300` exceeds Hobby's 60 s — lower it in the route and page.
- **0017 also** adds `'email'` to `invitation_channel` (invitations are inserted as clipboard, then best-effort
  updated to `email` when delivered) and an owner-only `update (auto_availability_links)` column grant + policy,
  mirroring 0015. Recipients: active promoters of non-suspended agencies with the switch on; welcome only for
  promoters created `active`; "send now" ignores the switch (owner's explicit act) and uses `manual-YYYY-MM-DD`.
