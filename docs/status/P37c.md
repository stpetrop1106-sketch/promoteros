## Done — summary for review
1. **Steps as built.** Drop anywhere on the page (calm full-page overlay) or button → type/size check with a plain sentence → SheetJS and the wizard load lazily → **Columns** (sheet picker defaulting to the first complete header, header-row override, each column with guessed meaning + 3 samples, <0.6 highlighted, every mapping a select, one column per meaning, mapping remembered per header signature with the "previous time" banner) → **Destination** (existing or new campaign with new/existing client, dates pre-filled from file min/max, rate; existing or new section defaulting to the file name; skipped with `target`) → **Stores** once per `StoreMatch` (exact collapsed, likely open and pre-selected, none must be decided; existing store select ranked by similarity; create geocodes server-side and shows where it landed, low confidence warned, failure disables create; skip) → **Preview** (every row with status and translated reasons, headline counts, new stores listed, in-file and DB duplicates excluded by default with toggles, "only problems" filter, button states exactly what it creates) → **Done** (created / left out by reason / link to `/shifts?campaign=…`).
2. **Server re-validates everything:** zod payload shape (real dates, `HH:MM` 00–23, headcount smallint, uuids), unique `sourceRow`s, `MAX_IMPORT_ROWS`, `checkBilling(…, "write")`; every row through `validateRow`; campaign, client, programme (must belong to the campaign, not archived) and every store id re-read through the RLS client, existing stores restricted to the campaign's client or unowned (same rule as the manual shift form); **`matchStores` re-run on the server and every resolution must equal a server StoreMatch by key and `sourceRows`**; rows joined to stores only through `sourceRows`; in-file duplicates recomputed on resolved stores (`validateRow` cannot); DB duplicates re-queried (cancelled shifts don't count); a "new" client that already exists is refused.
3. **Partial failure:** all reads, checks and geocoding happen before the first write, so every refusal writes nothing. Then client → campaign → stores → programme (`source='import'`, `source_filename`) → shifts in batches of 200, each carrying `programme_id`. A failed step stops everything after it; the outcome lists exactly what exists (client/campaign/stores/section, N shifts created, M not) and says how to recover: drop the same file into the same section again (created shifts are then excluded as duplicates) or archive the section. No shift is ever inserted before its programme exists.
4. **Double submit:** a ref guard in the wizard (verified: two synchronous clicks → one POST) plus a server check refusing a new import section with the same name and filename created in the last 120 s.

## Notes for the manager
- **Geocoding:** Nominatim finds nothing for "Λεωφόρος Βουλιαγμένης 100, Γλυφάδα" but finds "Βουλιαγμένης 100, Γλυφάδα". `plan.ts#geocodeQueries` therefore tries address+city, then the address without a leading street type (Λεωφόρος/Λεωφ./Οδός/Πλατεία), then name+city — never the city alone (a city centre would silently break the check-in geofence). The same normalisation would help `lib/geocoding` for promoter addresses (not my lane).
- The commit geocodes again itself; the stores-step location is shown, never trusted. Nominatim's 1 req/s queue means a file with many new stores takes that many seconds at commit.
- In-file duplicates are **excluded by default** (contract says warning); same treatment as DB duplicates, so nothing that doubles a shift is created unseen.
- The commit payload drops `issues` and `notes` (server recomputes issues; shifts have no notes column) to stay well under the 1 MB server-action body limit at 2000 rows. The "Σημειώσεις" mapping is labelled "(δεν αποθηκεύονται)".
- A "new" client that matches an existing name (case-insensitive in the wizard, exact on the server) is refused rather than upserted: an upsert would silently change which stores the import may match.
- Seed data (not mine): the dev database has a campaign client named "Kritikos Foods" — Kritikos is a real Greek supermarket chain, which may conflict with CLAUDE.md constraint 1.
