## Notes for the manager — what P37c should know

- **Header scoring**: each of the first 15 rows is scored by summing per-cell confidence
  (1.0 exact normalised match to a synonym, 0.8 all-tokens-present for a multi-word synonym, 0.75
  single-token exact match, 0.5 substring fallback, 0 no match) plus a small bonus per distinct field
  matched, so a row with many different fields beats a row that repeats one lucky match. Best-scoring
  row wins; ties keep the earliest row. A header-less file scores 0 everywhere and comes back with
  `complete: false` rather than throwing.
- **Dates**: real `Date` cells and Excel serials are read back via UTC getters (never a local-timezone
  read, matching the trap `lib/availability-links.ts` documents). Text formats: ISO `yyyy-mm-dd`;
  day-first `dd/mm/yyyy`, `dd-mm-yy`, `dd.mm.yyyy` (2-digit years become 20xx); a leading weekday word
  is stripped before parsing. No year → the next occurrence of that month/day on or after
  `options.today`, correctly crossing a New Year in either direction.
- **Times**: Excel day-fractions; `HH:MM`, `HH.MM`, bare `HH`; Greek AM/PM markers glued with or
  without a dot/space (`10π.μ.`, `18:00μμ`, `6μμ`). `time_range` (`10:00-18:00`, `10.00 – 18.00`,
  `10:00 έως 18:00`) wins over separate start/end columns whenever the range cell is non-blank —
  even if it then fails to parse, it does **not** silently fall back to the separate columns (that
  would mask a genuinely bad cell as a merely-missing one). `end <= start` is always `end_before_start`,
  never treated as overnight.
- **Store matching**: key = alphabetically-sorted normalised tokens of name(+address), so word order
  and spelling noise never split one store into two. Exact key match → score 1.0 → `"exact"`. Otherwise
  Jaccard similarity of tokens against every known store: **≥0.95 → `"exact"`, ≥0.6 → `"likely"`,
  below that → `"none"` with `match: null`**. That 0.6 floor is deliberately above the ~0.5 two
  same-chain-different-area stores score (e.g. "Hyper Vega Γλυφάδα" vs "Hyper Vega Κηφισιά" share 2
  of 4 tokens), so the UI never gets a false "likely" for that case.
- **One documented gap in the frozen contract**: `validateRow(row, options)` only receives the
  already-parsed `ParsedRow`, not the original cell text. `unparseable_date`/`unparseable_time`/
  `bad_headcount` all currently collapse into a null/defaulted field indistinguishable from a
  genuinely blank one — so on a server re-validate pass, a row the browser flagged
  `unparseable_date` will come back `missing_date` instead (same severity, same "this row needs
  attention" outcome, just a less specific code). `duplicate_in_file` similarly can't be
  reconstructed by `validateRow` since it has no sibling rows to compare against. Every other code
  (`missing_date`, `missing_store`, `missing_time`, `end_before_start`, `past_date`) round-trips
  exactly — verified in `tests/import-row-parser.test.ts`. Flagging this in case P37c's "confirm on
  the server" step wants to special-case those three codes (e.g. treat both `missing_*` and
  `unparseable_*` as equally blocking, which they already do since both are severity `error`/`warning`
  as appropriate) — I don't think it needs a contract change, just awareness.
- Import convention: import from `lib/import/index.ts` for the full surface (this pulls in `xlsx`
  transitively because `readWorkbook` lives there too). A server action that only needs
  `validateRow`/`matchStores` and wants to avoid bundling SheetJS should import those two directly
  from `lib/import/row-parser` / `lib/import/store-matching` instead of the barrel.

## Manager review — 2026-09-13

Returned for two duplicate-store bugs; the agent was killed by the session limit before starting the
fix, so the manager made it. Three failures, each reproduced with a failing assertion first:

1. **Address in the identity key** — a store with its address on the first row and blank below became
   two stores. Identity is now the name; the address splits a name only when the file carries two or
   more different addresses for it; blank rows join when there is at most one.
2. **Greek inflection** — "Γλυφάδας" did not match a known "Γλυφάδα". Tokens are now folded
   (`foldToken`: final ς/s and trailing vowels, words of 4+ letters, result keeps 3+).
3. **Found while fixing: similarity used name + address tokens**, so a known store with an address
   scored below 0.6 against a file row without one. Similarity is now name-only; the address breaks
   ties between known stores sharing a name.

**Contract change, additive:** `StoreMatch.sourceRows: number[]`. **P37c must join rows to stores with
`sourceRows`**, never by recomputing `normaliseStoreKey` per row — a blank-address row's store depends
on the rest of the file.

Tests: `tests/import-store-identity.test.ts` (11) and `tests/import-acceptance.test.ts` (manager's
messy-Greek-file probe). All 88 import tests green; the chain/area guard still holds.
