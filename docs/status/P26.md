## Notes for the manager
- `app/onboarding/actions.ts` had five violations, not two: alongside `CREATE_AGENCY_IDLE`, the
  dependent types `Timezone`, `CreateAgencyErrors`, `CreateAgencyState` and the runtime constant
  `TIMEZONES` all had to move together to `app/onboarding/state.ts`, since `CreateAgencyState`
  depends on `CreateAgencyErrors` and the form reads `TIMEZONES` at runtime for the dropdown (it's
  not action state, but it's `app/onboarding`-only data, so it lives in the same file per the
  parcel instructions).
- Least obvious consumer: `app/onboarding/agency-form.tsx` imported `createAgency` (async, stays
  in `./actions`) alongside `CREATE_AGENCY_IDLE`/`TIMEZONES`/`CreateAgencyState` (moved) from a
  single `./actions` import — had to split it into two imports rather than just swap the path.
  Same split was needed in `report-form.tsx`... actually not needed there (only state.ts symbols),
  but was needed in `agency-form.tsx`, `accept-form.tsx`, `promoter-form.tsx`, and
  `billing-controls.tsx`, all of which imported an async action function and state symbols from
  the same `./actions` line.
- Build surfaced nothing beyond the six files in the brief. Confirmed by grepping every
  `**/actions.ts` under `app/` for `^export const `/`^export function ` after the fix — none
  remain. Several other `actions.ts` files (`app/i/[token]/actions.ts`, `app/shifts/[id]/
  actions.ts`, `app/campaigns/**/actions.ts`, `app/c/[token]/actions.ts`, `app/login/actions.ts`)
  export `type` declarations directly — left alone, since `export type` is erased at compile time
  and never reaches the client as a runtime `undefined`, so it isn't an instance of this bug.
