**How to mint a check-in token for a seeded assignment.** As of this check, the seeded database
has 24 shifts, `0` invitations, and `0` assignments — no confirmed assignment exists yet, so
there's nothing to check in to until one is created. Two ways to get there:

1. **Through the real flow (exercises P7 too):** open a shift in the coordinator UI, invite a
   candidate, open the `/i/[token]` link that produces, and accept it. That inserts a
   `confirmed` row into `assignments`.
2. **Fast path for testing only:** insert a row directly —
   `insert into assignments (agency_id, shift_id, promoter_id) values ('<agency_id>',
   '<shift_id>', '<promoter_id>')` — `status` defaults to `'confirmed'`.

Either way, once you have a confirmed assignment's id, mint its link. `lib/checkins.ts` and
`lib/invitations.ts` both start with `import "server-only"`, so they cannot be imported from a
bare script — I verified this by trying (it throws `This module cannot be imported from a Client
Component module`). `lib/tokens.ts` and `lib/supabase/admin.ts` carry no such guard, so the same
thing `createCheckinLink` does can be run directly:

```
npx tsx --env-file=.env - <<'EOF'
import { createAdminClient } from "./lib/supabase/admin";
import { mintToken, linkFor } from "./lib/tokens";

const db = createAdminClient();
const { data } = await db.from("assignments").select("id").eq("status", "confirmed").limit(1).maybeSingle();
if (!data) { console.log("no confirmed assignment yet"); process.exit(0); }
const { token } = mintToken("checkin", data.id, 24 * 3 * 3600);
console.log(linkFor(token, "checkin"));
EOF
```

I ran this (read-only — it only selects and computes an HMAC locally, no writes) to confirm the
path works; it correctly reported "no confirmed assignment yet" against the current database. I
deliberately did not insert a test assignment myself, to avoid mutating a database another agent
may be relying on a specific seeded shape of right now (`scripts/seed.ts` is being rewritten in
parallel). Once you have a real link, open it on a phone over the deployed HTTPS URL —
`localhost` is exempt from the secure-context requirement for geolocation, a LAN IP is not.
