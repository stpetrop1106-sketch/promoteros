- **`lib/programmes.ts`**: mapping (snake_case DB rows → camelCase), aggregation (coverage, date
  range, next-shift-date per section), ordering, filtering, and filter-dropdown option builders —
  all pure, no `server-only`. Every DB-touching function (`fetchProgrammeBoard`, `createProgramme`,
  `renameProgramme`, `setProgrammeArchived`, `listCampaignProgrammes`) takes an already-created
  RLS-scoped client as a parameter instead of creating one, and `createServerSupabase` is imported
  only as a type (`import type`, used solely in a `typeof` position) — that's what lets
  `tests/programmes.test.ts` import the module under plain Node without the `server-only` package
  throwing (it throws unconditionally outside a Server Component / react-server condition).
  `fetchProgrammeBoard` is **2 queries total for the whole board**, independent of section count:
  one for `shift_programmes` (joined to campaign/client names), one for every shift (joined to
  store/campaign/client names and `assignments(status)` for coverage). Aggregation, sorting and
  filtering all happen afterwards in TypeScript, same split as `app/dashboard/page.tsx` +
  `lib/exceptions.ts`. Ordering: sections with an upcoming (not-cancelled, on/after today) shift
  sort by that date ascending; a brand-new section with zero shifts stays near the top (it needs a
  different kind of attention, not none); a section whose shifts are all in the past sinks to the
  bottom, most-recently-finished first. Filters (client, campaign, upcoming/past/all, archived)
  are pure functions over the aggregated list, applied after sorting.
