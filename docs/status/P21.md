2. **Rate limiting.** `lib/waitlist/rate-limit.ts` + `supabase/migrations/0010_waitlist_hardening.sql`.
   Database-backed (a `waitlist_rate_limit` table, not an in-memory counter — a serverless
   in-memory counter resets on every cold start, i.e. no real limit). IP is read from
   `x-forwarded-for` via `next/headers`, HMAC-hashed with `TOKEN_SIGNING_SECRET` before it
   ever reaches the database — the raw IP is never stored. ~3 submissions/IP/hour via an
   atomic `increment_waitlist_rate_limit` upsert (plain select-then-write from app code would
   race two concurrent requests from the same IP), plus a 200/hour global circuit breaker.
   Opportunistic cleanup deletes rows older than two windows on every check, so the table
   stays bounded without a scheduled job. A tripped limit returns a specific
   `waitlist.status.rate_limited` message, never a silent success or "something went wrong".
   Fails OPEN on a database error reaching the rate-limit table itself (the insert that
   follows would fail on its own if the database were really down, so failing closed here
   would just add a second silent way to lose a real signup).
