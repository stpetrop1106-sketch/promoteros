## Notes for the manager

**What it detects.** All eight §8 cases, from the existing schema: under-covered shift near its
start; pending invitation about to expire; invitation already expired unanswered; a decline that
leaves the shift short; a cancelled assignment; a started shift with no check-in past a 15-minute
grace; a check-in outside the geofence; a manual-override check-in (informational); and a completed
assignment with no field report.

**How it ranks.** Severity first, then `minutesUntilHarm` ascending, then type and id for a total
order. Severity is *derived from* urgency rather than fixed per type — the same under-covered shift
is `critical` four hours out and `warning` two days out — so leading with it is still sorting by
urgency; it only stops a stale informational row from outranking a live one because its clock reads
further into the past. Negative `minutesUntilHarm` sorts first, so a promoter missing from a store
right now beats a shift starting in thirty minutes. Tested both ways round.

**What I deliberately did not treat as an exception.**
- An under-covered shift more than 72 hours out. That is the backlog, and putting it here would
  bury the fires — which is the exact failure `/shifts` already has.
- A decline or cancellation on a shift that has since been covered, or older than 48 hours. If the
  seat is still empty it is already reported once as under-coverage; a second row is noise.
- A no-show the coordinator has already marked. The work is done; the empty seat it leaves is
  reported once, as under-coverage.
- A cancelled shift, at all — it is the one status that removes work.
- **A manual-override check-in is surfaced but never as a failure** — `info` severity, its own
  colour, and Greek that says so out loud ("δεν είναι πρόβλημα"). CLAUDE.md §3: the manual path
  exists precisely so location is never the sole gate on being paid; flagging its use red would
  quietly undo that.
- **"Time change" and "location change" from §8 cannot be detected today.** Nothing records the
  previous value of `shifts.on_date`, `start_time` or `store_id` — the rows are overwritten in
  place. That is `build-plan.md` §11.2 **G8** (audit trail on assignments, invitations and
  check-ins). Once G8 lands, both are a small addition here. I did not fake them from `created_at`.

**Two smaller decisions.** Greek names appear without the article ("Μαρία δεν έχει κάνει check-in",
not "Η Μαρία…") because the article is gendered and `promoters.gender` is optional — clipped, but
never wrong about someone. And `lib/exceptions.ts` carries its own copy of the Athens wall-clock
helpers rather than importing `app/shifts/[id]/time.ts`, which sits in a directory this parcel does
not own; the reasoning is identical and documented in both.

**Not verified in a browser.** The page needs an authenticated coordinator session, and creating
one means a magic-link sign-in with someone's real address — not something I will do. Evidence is
the green production build with `/dashboard` in the route table, a clean typecheck, and the unit
tests. A human should open it once with real seeded data before this goes to `done`.

**One environment note, not a code issue.** `npm run build` failed twice mid-session with
`EINVAL: invalid argument, readlink` on files inside `.next/`. That is OneDrive dehydrating build
artifacts into cloud placeholders, not this parcel. `rm -rf .next` and rebuild fixes it; worth
knowing before someone debugs it as a real build break.
