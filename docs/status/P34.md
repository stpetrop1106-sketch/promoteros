## Done
- The token foundation, the type scale, elevation, and the upgraded kit (run 1).
- **Mobile.** The drawer is now a real dialog: `role="dialog"`, `aria-modal`, `aria-label` from
  `nav.label`, focus moved into it on open and returned to the hamburger on close, Tab cycled
  inside it, Escape closing it, and the body scroll lock released on every exit path. It also
  closes itself when the viewport crosses the `lg` breakpoint — without that, widening a window
  while the drawer was open left `overflow: hidden` on `<body>` and no visible control to release
  it. The drawer panel and the desktop rail both scroll internally (`min-h-full`, not `h-full`),
  so a short landscape phone can still reach the settings row.
- **Promoter pages carry no agency chrome.** Verified in a browser at 375px: `/i/[token]`,
  `/c/[token]` and `/a/[token]` render `<main>` as a direct child of `<body>` — zero `<nav>`
  elements, no shell wrapper, no offset, no empty header, no horizontal overflow.
  One real leak found and closed: the billing banner was passed to `AppShell` as a *child*, so a
  coordinator who was signed in and opened their own invitation link showed the promoter an agency
  payment warning. It now goes through a new optional `banner` prop that is gated by the same
  hidden-path check as the navigation.
- **Kit pass.** Button heights are `min-h-*` + padding rather than fixed `h-*`, so a Greek label
  that wraps grows the button instead of spilling out of it (single-line metrics are unchanged at
  36/44/48px); disabled state raised to `opacity-50` with the ring dropped. Field controls no
  longer darken their border on hover while disabled. `StatTile` labels wrap to two lines in a
  fixed-height box instead of truncating, so the numbers stay on one baseline. `Table` gained a
  pure-CSS edge shadow that appears only on a side that can actually scroll, an optional `label`
  (the unnamed `role="region"` is gone; `tabIndex` stays), and an optional `layout="fluid"` for a
  table carrying a prose column.
- `docs/design.md` — palette with intent per colour, type scale, elevation, radius, spacing
  rhythm, the shell contract including the promoter-page rule, a "reach for which component"
  table, the five interaction states, touch/narrow-screen rules, and how to extend the system.

## No component API changed

Everything added in this run is optional with a default that reproduces the previous behaviour:
`Table`'s `label` and `layout`, and `AppShell`'s `banner`. The original `AppShell({ signedIn,
children })` call still compiles.

## Verified by looking
Built and served a clean production build from an isolated copy (`C:\dev\p34-check`) on its own
port, because the dev servers on 3000 and 3100 were both 404ing their CSS chunks. The browser
profile had a live coordinator session, so the signed-in screens *were* reachable — the dashboard,
`/shifts` and `/promoters` were all seen rendered, at 375px and at 1360px.

Seen: the mobile top bar, the drawer open with its active pill and pinned settings row, the
desktop rail, the kit on a phone, `/promoters`' table scrolling inside itself (1738px of content
in a 325px box) with the page itself not overflowing, and the full open → Escape → closed cycle
releasing the scroll lock and restoring focus.

**Not seen, stated plainly:** the close-on-breakpoint-crossing guard. This harness's viewport
emulation changes `window.innerWidth` while dispatching no `resize` event, no media-query
`change`, and not even a `ResizeObserver` callback on the document element — all three were
instrumented and all three stayed at zero, so no page-level code could detect that resize. The
guard listens for `change` and `resize`, which a real window resize fires by spec. It needs a
human dragging a real browser window.

## What a per-screen pass should still fix
- `/shifts` renders a raw `<table>` rather than the kit's `<Table>`, so it has no card frame and
  its "signed in as / sign out" row runs off the right edge on a phone. That file belongs to
  another lane.
- `SelectField` labels clip inside narrow filter bars ("Όλες οι καταστάσ"). The control is doing
  the right thing; the filter-bar column widths on `/promoters` are what need loosening.
- Nothing in the app uses `Skeleton`, `StatTile`'s `action` slot, or `Table`'s new `layout="fluid"`
  yet. The exception dashboard and the campaign report are the obvious first customers.
